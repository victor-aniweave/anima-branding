# ANIMA 交付前自檢守則　v1

給設計團隊。每次交付前，依本守則跑一遍，交付時附上 §6 格式的自檢報告。

**表格不重複維護**：本守則不內嵌資產表、詞彙表、色彩對比表的複本。凡是「品牌規範」相關的資料（slogan、tagline、禁用詞、事實基線、色彩對比規則），一律呼叫 `anima-brand` skill 讀取最新版，不用本檔的舊資料比對——避免兩邊各自過期、各說各話。

---

## 0. 三個原則

1. **有來源才算檢查。** 每一項要寫「對照哪份文件、用什麼方法」。方法只有兩種：搜尋字串（寫命中次數）、逐行讀（寫行號或段落）。**沒有方法的「已確認」不算**，一律視為不合格、要求重新執行。
2. **空白不要填。** 事實、數字、資產位的新句子，沒有給就標【待確認】。不猜、不補、不順手潤。
3. **改一處，同類全改。** nav、footer、信箱、Demo 時長、標籤單複數，改了一頁就要改全部頁。
4. **什麼時候找 ANIWEAVE：只有報告第 5 項【待確認】有內容的時候。** 其餘依 §5 自修或自決，報告寫清楚即可，不用等確認。

## 1. 來源文件與優先序

| 優先 | 文件 | 管什麼 |

| 1 | 本守則 §2 事實 | 統編、Demo 規則、產品名限制、「不出現」清單 |
| 2 | `anima-brand` skill（呼叫 Skill 工具讀取最新版） | 事實基線、聲線、詞彙表、資產表、對比色規則、版位結構、署名／信箱／LINE |
| 3 | 該頁的 brief | 原話、結構、該頁不要編的東西 |
| 4 | ANIWEAVE 該輪的修訂建議檔 | 該輪要改的清單 |

衝突時上位優先。

## 3. 通用檢查（每次都跑）

### 3.1 資產逐字

資產位：字卡、H1、H2、tagline、CTA 主標、頁尾標語、meta title 與 description。資產位的句子必須逐字（含標點）來自 `anima-brand` skill 的資產表（定案 slogan、Tagline、Lockup 規則、影片字卡、可用文案、退役句，見該 skill §4 與 `references/examples.md`），用搜尋字串比對，不用目測。

- [ ] 每個資產位的句子在 `anima-brand` 資產表逐字命中
- [ ] 資產位出現不在表上的句子 → 標「草案」，列入報告，不自行定案
- [ ] 退役句（`anima-brand` references/examples.md）0 命中
- [ ] Lockup 位有省略主詞；純文字位有帶主詞

### 3.2 詞彙與語感

禁用詞比對 `anima-brand` skill §3 詞彙表（核准用語／禁用與替換），搜尋命中應為 0（詞彙表本身與 ✗ 範例除外）。

- [ ] 禁用詞命中 0
- [ ] 驚嘆號 0
- [ ] 排比句、形容詞堆疊 0
- [ ] 英文 sentence case、句尾有句號；英文句中 agent 小寫
- [ ] 中文全形標點
- [ ] 內部註記 0 外露：正式標籤／待老闆確認／提案中／示意／TODO／【】占位符
- [ ] 唸出來像人講話；老闆在飯局講得出口

### 3.3 事實與架構

- [ ] 本守則 §2 逐項核對，命中值一致
- [ ] `anima-brand` skill §1 架構事實不違反：一家公司一個專屬 ANIMA，有自己的 LINE 官方帳號；由 ANIWEAVE 建好再交付；對外由人把關。以下字串 0 命中：加好友就開始／掃碼即用／自助註冊／自動幫你回覆／公開帳號
- [ ] 沒有編任何數字
- [ ] 規範類文件裡模糊規則詞 0：盡量／儘量／適當／一定（作程度用）／視情況

### 3.4 結構與一致性

- [ ] 同一份文件不自打架：規則與封面／示範一致；定位語一套
- [ ] 跨頁一致：nav 標籤、footer 全部欄位、信箱、Demo 時長、中英與單複數
- [ ] 狀態標籤：一組卡要嘛全有，要嘛全無
- [ ] 佔位符（素材製作中等）列清單，交付時寫數量與預計替換時間

敘事頁四檢（About 類）：

- [ ] 頂部每個宣稱，下方有一張卡替它作證
- [ ] Hero 提到的名字或概念，內文有接回來
- [ ] 結論句出現在證據之後，不先辯護
- [ ] brief §1 原話逐字（比對前先去掉 markdown 粗體標記）

### 3.5 視覺

- [ ] 表示轉變不用箭頭、分岔、轉彎；文字箭頭標籤不放大成圖形
- [ ] 徽章、標籤質感只用於真正的狀態，不用於命名句
- [ ] 配色照 `anima-brand` skill §7 對比規則（含 text-secondary／text-tertiary 使用限制）
- [ ] 中英混排字重一致

## 4. 分類型附加檢查

### 4.1 品牌規範新版本

- [ ] 上一輪修訂清單逐條：原文 0 命中、改文 ≥1 命中，逐條列出
- [ ] 供稿段落關鍵句逐字命中
- [ ] 自己新增的句子全部列出，逐句過 3.1、3.2
- [ ] 示範位只放資產表的句子
- [ ] 版本號、頁尾公司名正確

### 4.2 網頁

- [ ] brief 的「不要編」清單逐項 0
- [ ] 時態與狀態規則照 brief
- [ ] 表單文案：不承諾時限；Demo 半小時

### 4.3 社群、影片、簡報

- [ ] 影片字卡逐字；字卡層與內文層不混

## 5. 修改的三個等級

| 等級 | 例子 | 做法 |
|---|---|---|
| 自修 | 錯字、截字、禁用詞替換、標點、大小寫、內部註記外露、跨頁同步 | 直接改，報告列出改了什麼 |
| 自決 | 結構搬動、段落分行、視覺處理、技術實作、其他設計判斷 | 直接做，報告寫做了什麼與為什麼；不用出執行計畫等確認 |
| 上報 | 事實、數字、品類詞、資產表增刪、資產位的新句子、§2 任何值 | 標【待確認】，不填、不做 |

## 6. 交付格式：自檢報告

每次交付附一份，結構固定：

1. 交付物清單：檔名、版本
2. 對上一輪清單：每條 落地／未落地／改法不同（一句說明）
3. 自檢結果：§3 與 §4 各項 過／不過／不適用；不過的附字串或行號
4. 自己新增的句子：逐句標 資產／草案
5. 【待確認】清單
6. 已知未完成：佔位符、時程

第 5 項為空，代表這次不需要 ANIWEAVE 確認，直接交付。

方法欄必填，格式：搜尋「字串」於 檔名，命中 N。**不接受沒有字串或行號的「已檢查」——一律視為不合格，要求重新執行。**

範例一行：

> 3.2 禁用詞：搜尋「對齊」於 About.html，命中 0；搜尋「你公司」於 About.html，命中 0。過。
> 3.1 資產位：搜尋「公司怎麼做，ANIMA 都記得。」於 About.html，命中 1（CTA 主標）。過。
> 3.3 事實：搜尋「hello@」於 About.html、Solution 兩頁，命中 0。過。

## 7. 執行方式

當使用者以 `/anima-delivery-check [檔名...]` 呼叫本 skill、或直接說「幫我對 [檔名] 跑一次交付自檢」時：

1. 讀取 `anima-brand` skill（取得最新的事實基線、詞彙表、資產表、對比色規則）
2. 讀取 args／訊息裡指定的檔名，把該檔案內容讀進來
3. 依 §3 與對應的 §4 類型，生成逐項可執行的檢查清單，每項寫測試方法（搜尋字串命中次數，或逐行讀的行號）與結果
4. 能自修的依 §5 直接修並列出；其餘標【待確認】
5. 輸出 §6 格式的自檢報告，不得省略、不得只回「檢查完畢、沒問題」這種沒有方法佐證的結論

沒有指定檔名時，預設檢查這次對話裡剛完成、準備交付的東西，並在報告開頭註明是依對話上下文判斷的檔案。

**省 token 原則**：只用文字方法核對（搜尋字串、逐行讀），不做非必要的螢幕截圖或視覺渲染確認——截圖本來就不算 §0 認可的方法，除非使用者明確要看視覺排版；同一次對話裡已經抓過的頁面內容或 skill 資料不重複抓取；若渲染工具因分頁未顯示而失敗，改用不需要渲染的讀取方式，不重試需要渲染的操作。

守則本身要改，只有 ANIWEAVE 能改；發現守則有漏，寫進報告第 5 項。
